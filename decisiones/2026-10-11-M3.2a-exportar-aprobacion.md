# M3.2a Exportar — aprobación de la construcción (opción A)

## Origen de esta anotación

**Fuente: autorización explícita del CEO, emitida en esta sesión (2026-10-11):** *«Apruebo el DP
DP-M3.2a-EXPORTAR-MODELO-USUARIO.md, opción A: conectar la exportación existente del modelo del usuario
mediante un formato neutral legible, conforme a la Bible vigente. Autorizo ejecutar el incremento
completo dentro del alcance aprobado, con pruebas RED→GREEN, integración, mutación, seguridad,
regresión, Quality Gate y revisión ECC. No se autoriza ampliar el alcance ni modificar CM2, S3 o M3.2b.»*

Se registra la decisión emitida; no se fabrica nada. El DP no se modifica como documento histórico.

## Alcance aprobado (opción A)

1. **Cablear** la capacidad de exportación ya existente (`modelo_usuario.py:107 exportar(user_id)`) a
   una **ruta autorizada para el usuario**, sin reconstruirla.
2. **Formato neutral legible** (Bible 4.1 §5 L64 «formato neutral», «el usuario es el dueño»). El
   artefacto NO se cifra: el cifrado es del almacén en reposo (4.1 §5 L62), requisito separado.
3. Validar permisos, integridad, portabilidad, aislamiento por `user_id` y manejo seguro.
4. Pruebas RED→GREEN, integración, mutación, seguridad, regresión + Quality Gate + revisión ECC.

## Lo que esta aprobación NO concede

- Ampliar el alcance más allá del cableado + formato neutral.
- Cifrar el artefacto exportado (opción B/C): no aprobada.
- Tocar el buffer `recent`, M3.2b, CM2, S3 ni CM1/R1.
- Modificar la Bible, ADR, `decisiones/` o el catálogo fuera de lo que exija el cableado.
- `commit`, `push` ni `merge`.
